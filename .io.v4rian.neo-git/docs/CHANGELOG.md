# Changelog

The v4rian git template's release history, in human readable form. Each section below corresponds to one `vYYYY.cycle.dev` tag landed on `dev` via the claim flow. Tags are the canonical seal of every release; this file is a companion that summarizes the substantive feature, fix, refactor, and docs commits behind each tag. Pure merge subjects and `chore(version)` plumbing commits are omitted; the full reachable history is always one `git log` away.

## Unreleased

Replaces the auto-rebase reconcile branch's rename plus tmp plus delete dance with a force-push rolling pointer. A reconcile candidate is machine-owned rewritable state, not developer history, so on every dev advance the pass rebuilds it from scratch against the new dev tip and force-pushes the canonical `pool/*.reconcile.*` name in place. The old atomic-vacate to a tmp slot could not run on a repo without the CI bot App enrolled, because deleting a pool ref needed a bypass identity the plain workflow token lacked, so a second dev advance under an open PR left the message "could not atomically rename the prior reconcile branch". The force-push needs no bypass and no admin: `pool-creations` carves reconcile out so the first cut lands, `pool-deletions` only fires on a delete and never on an update, and the no-force rule binds only the developer's own pool branch, never the machine-owned candidate. CI never deletes a pool ref. The developer's own `pool/*` branch is never force-pushed. The lifecycle suite gains `auto-rebase reconcile force-pushes candidate (not delete)` plus an end to end iterative proof, scopes the never-force-push gate to the developer branch, and keeps the `pool-deletions` lock covering every pool ref.

Closes the reconcile-visibility gaps surfaced by the first consumer-driven release cycle. A successful auto-rebase pass now links the reconcile candidate on the original PR via a recap comment carrying a one-click `compare/dev...<recon>?expand=1` quick-link, so the admin can review and merge reconciled work without waiting for the developer - the original PR is still never closed and the developer's pool branch is never pushed to, preserving the sovereignty rule for the branch while removing its hold on the project timeline. A reconcile commit status on the original PR's head reports pending at pass start and resolves per outcome, putting the in-flight state where the admin looks instead of only in comment bodies. Archive pushes honor the claim token so the vault rename and pool delete stop failing under the bypass-less workflow token. The claude install in the dispatch runner moves to the background with a completion marker the library joins on, cutting roughly twenty-five seconds from the time between a dev merge and the first PR-facing reconcile signal.

Hardens the consumer bootstrap and lifecycle against seven silent failure modes found by standing up the first real consumer (fractaris). Bootstrap step 1 now SETS the repository Actions toggle in apply mode, re-reads it for truth-from-state, and aborts when it does not stick, instead of advising the operator non-fatally while every event-triggered gate silently never ran. Bootstrap dispatch accepts an optional claude_token input that step 9b writes as the CLAUDE_CODE_OAUTH_TOKEN secret and verifies, so the claude-judgment audit layer arms during bootstrap; dispatching without one warns at the wrapper and paints a red run-summary item. The validator reports the release status context on PRs into main, gated on the release version resolving, closing the permanently-expected required check that previously merged only through admin bypass. Framework canaries gate themselves off consumer repositories at the resolve step. The ci-dispatch enumerator carves out the merge-claim audits for consumers so merge claims and version tags exist outside the framework repo. A zero-script matrix writes a run-summary warning so an empty dispatcher can never read as executed gates. The allocator forwards the dispatching admin's token for pool and safety ref creation, working around GitHub's refusal of the github-actions Integration as a bypass actor from non-workflow ruleset sources; the ruleset strip-retry warns honestly instead of celebrating, and the allocation wrapper announces its dispatch, fails loudly on a refused dispatch, and exits non-zero when no run materializes.

Fixes the auto-rebase post-merge pass so the reconcile candidate carries the full pool delta on multi-commit pool branches and never pushes an empty branch. The prior implementation computed the cherry-pick base as the parent of the pool tip, which collapsed the range to the single top commit on any pool branch with more than one commit and silently dropped the rest from the reconcile branch. The base is now the merge-base of the pool tip and the current dev tip, which is the correct common ancestor and produces a cherry-pick range covering every pool commit since the divergence. A new guard between the cherry-pick loop and the push sites refuses to push a reconcile branch whose tip equals dev tip (zero pool commits actually landed); in that case the script posts a PR comment that names the empty-reconcile state explicitly so the admin understands the pool needs a hand-rebase instead of mistaking the absence of content for a clean reconcile. A new lifecycle e2e assertion stands up a 3-commit pool branch and counts the commits on the resulting reconcile branch to catch the regression class, and the existing L5 surface assertion is updated to match the new empty-reconcile contract.

Removes the force-push and close-and-supersede paths from the auto-rebase pass and codifies the how-git no-rewrite-history principle into the script's behavior. Previously, on a clean rebase against the new dev tip, auto-rebase force-pushed the rebased commits back onto the developer's pool branch (rewriting their history with new SHAs), and on a conflict it opened a separate `[RECONCILE]` PR and closed the original with a forwarding comment (closing the developer's PR on their behalf). Both paths violated the principle that the developer is sovereign in their `pool/*` sandbox and that the admin is the sole merge decider on dev. The rewrite makes the reconcile-branch path the only path: for every open pool→dev PR, the auto-rebase pass cuts a fresh `pool/nN.reconcile.<short>` candidate off the new dev tip, cherry-picks the pool's commits onto it (claude L1-L5 ladder on any conflict), pushes the reconcile branch as a CREATE (CI fires normally on the new ref without any PAT plumbing), and **comments on the existing PR** with the reconcile candidate and a recap. The original pool branch and the original PR are never touched. The admin reviews and decides: merge the reconcile candidate locally, tag the developer for changes, or close the PR to reject. The developer also owns the pool branch and can push their own resolution at any time before admin review; if they do, the reconcile candidate stays on origin as a receipt only.
